# Developer key and validation API — design

**Date:** 2026-09-05 · **Repo:** `~/meridian` (canlicapital.com) · **Status:** approved in chat, spec for review

## 1. Goal

Give people and companies a free, keyed API that runs their own strategy numbers through the same
honesty arithmetic this house runs on itself, and hands back a verdict they can cite and anyone can
recompute. It does not hand out market data, because every source in
`config/data_source_rights_policy.json` forbids raw redistribution. The engine is the product.

Non-goals: streaming, paid tiers, storing anyone's returns, signing receipts with the transparency
key (that key stays on the Mac by design), and any endpoint that touches a broker or the trial
ledger.

## 2. Surface

All routes live under `/api/v1/` beside the existing static read API. The static endpoints are
unchanged and stay keyless.

| Route | Method | Key | What it does |
|---|---|---|---|
| `/api/v1/keys` | POST | no | Issue a free key. Body `{ "label"?: string }`. Returns the key once. |
| `/api/v1/validate/deflated-sharpe` | POST | yes | PSR, DSR, expected best-by-luck Sharpe, search haircut. Accepts the seven contract inputs OR a return series plus trials and dispersion. |
| `/api/v1/validate/overfitting` | POST | yes | Probability of backtest overfitting by CSCV over a T×N returns matrix of the variants tried. |
| `/api/v1/validate/paper-evidence` | POST | yes | Conformance of a record against `canli.paper-evidence.v0` (structural + semantic). |
| `/api/v1/validate/breadth` | POST | yes | Book Sharpe ceiling `s̄/√ρ̄`, sleeves required for a target, ceiling captured. |
| `/api/v1/receipts/{id}` | GET | no | A stored verdict by content-hash id. Immutable, cacheable. |
| `/api/v1/validate/status` | GET | no | Service, store and quota constants. Also the keep-alive probe. |

### The envelope

Every response, success or error, is the existing envelope from `scripts/build-api.mjs` with two
additions. `claim_class` gains the value `USER_SUBMITTED_SCENARIO`; `capital_kind` for user data is
`NOT_APPLICABLE_USER_SUBMITTED`. Fields: `schema` (`canli.api.v1`), `endpoint`, `generated_at`,
`claim_class`, `capital_kind`, `canonical_human_page`, `limits` (non-empty, build refuses otherwise),
`sources` (path + sha256 + url of every contract and core the verdict is bound to), `data`, and on
POST validators `receipt` (`{ id, url, input_sha256, output_sha256 }`). Errors add `error`
(`{ code, message, pointer? }`) with an empty `data`. Quota headers on every keyed call:
`X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`.

Every validator's `limits` state, verbatim: the verdict is about the series as submitted; the
service never saw the data source, its costs, survivorship, or lookahead; a deflated Sharpe above
any threshold is not admission to anything; the receipt is content-hashed and reproducible from the
open-source core, not signed.

### Public quotas (single source: `api/_lib/limits.js`; the docs and OpenAPI import it)

| Constant | Value |
|---|---|
| Validations per key per UTC day | 1,000 |
| Keys issued per client per UTC day | 5 |
| Request body | 1 MiB |
| Observations per series | 20,000 |
| Variants in an overfitting matrix | 200 |
| CSCV combinations evaluated | 2,000 (of C(16,8)=12,870; sampled with the declared seed) |
| Function wall time | 10 s |

## 3. Architecture

```
api/
  v1/keys.js                        issue keys
  v1/validate/deflated-sharpe.js    one handler per validator
  v1/validate/overfitting.js
  v1/validate/paper-evidence.js
  v1/validate/breadth.js
  v1/validate/status.js
  v1/receipts/[id].js
  _lib/envelope.js                  the envelope + error envelope (mirrors build-api.mjs)
  _lib/limits.js                    the quota constants, imported by docs, OpenAPI and handlers
  _lib/store.js                     Supabase REST client (fetch; no SDK), all writes via RPC
  _lib/auth.js                      key parsing, sha256 at rest, quota consume
  _lib/canonical.js                 canonical JSON (sorted keys) + sha256, matches canonical-json.mjs
  _lib/body.js                      size-capped body read, strict JSON, numeric coercion rules
js/
  dsr-core.js                       calculateDsr + normalCdf/Ppf, NO DOM (extracted from dsr-tool.js)
  moments-core.js                   per-period Sharpe, biased skew, non-excess kurtosis
  pbo-core.js                       CSCV port of alphaforge.validation.pbo.pbo_cscv
  breadth-core.js, paper-evidence-core.js   reused as they are
standards/validation-api/vectors.json       parity vectors generated by Python, committed
```

Vercel Node functions (the `api/waitlist.js` convention: `export default async function handler`).
No new npm dependencies: Supabase is called over REST with `fetch`, exactly as the waitlist
function does. The cores are plain ES modules shared by the browser tools and the functions, so
the tool on `/tools/deflated-sharpe` and the API cannot disagree.

### Store (Supabase project `canlicapital`, ref `bpnensyowfmdwhqmfdrg`, eu-central-1, free tier)

```sql
api_keys           (id uuid pk, key_hash text unique, label text, tier text default 'free',
                    created_at timestamptz, last_used_at timestamptz, revoked_at timestamptz)
api_usage_daily    (key_id uuid fk, day date, calls int, pk (key_id, day))
api_key_issuance   (client_hash text, day date, issued int, pk (client_hash, day))
receipts           (id text pk, key_id uuid fk, endpoint text, input_sha256 text,
                    output jsonb, bindings jsonb, created_at timestamptz)
```

Row Level Security enabled on every table with no anon or authenticated policies: the only caller
is the function with the service-role key from Vercel env. Two RPCs, `SECURITY DEFINER`, are the
only write paths: `consume_quota(key_hash, daily_limit)` (atomic upsert-increment, returns
remaining or −1 when exhausted or the key is unknown/revoked) and `issue_key(client_hash,
daily_limit, key_hash, label)`. Mutation test for the RLS posture: an anon-key `select` on every
table must return zero rows and no error (the pattern from `reference_supabase_rls_hardening`).
Keep-alive: `/api/v1/validate/status` performs one read; the Mac's health run calls it daily so
the free-tier project is never paused for inactivity.

Stored: key hashes, daily counters, hashed client identifiers (sha256 of IP + a daily salt from
env), and receipts. Never stored: submitted returns or matrices, raw IPs, labels beyond 64 chars.

### Keys

`ck_live_` + 32 random bytes base64url. Only `sha256(key)` is stored. The response returns the key
once with the quotas and a line saying it cannot be recovered. Issuance is limited per hashed
client per day. Revocation is a manual SQL update; the API has no revoke endpoint in v1.

### Receipts

`id` = first 24 hex of `sha256(canonical({ endpoint, input_sha256, output, bindings }))`. The
`bindings` object lists the sha256 of each core module and contract the verdict used, so a reader
can fetch the same core from `/engineering` and recompute. `GET /api/v1/receipts/{id}` returns the
envelope with `Cache-Control: public, max-age=31536000, immutable`. Receipts contain no key id and
no submitter identity.

## 4. Validators

**deflated-sharpe.** Input A: the seven contract fields of
`deflated_sharpe_calculator_contract.json`. Input B: `returns: number[]`, `periods_per_year`,
`effective_independent_trials`, `cross_trial_sharpe_sd_annualized`; moments are derived exactly as
`alphaforge.validation.dsr._per_period_moments` (sample std ddof=1 for the Sharpe; biased skew;
biased non-excess kurtosis; zero-variance series rejected). Output: the `calculateDsr` object plus
`derived_inputs` when B was used. Bound to the contract sha256 and `dsr-core.js` sha256.

**overfitting.** Input: `matrix: number[][]` (rows = time, columns = variants), optional
`n_splits` (even, default 16), `seed` (default 42). Port of `pbo_cscv`: contiguous blocks, block
Sharpe with population std and `-inf` for zero variance, IS-best by argmax, OOS rank by average
ranks, `omega = rank/(N+1)`, `lambda = logit(omega)`, `pbo = mean(lambda <= 0)`. Output: `pbo`,
`n_combinations`, `lambda_quantiles`, `is_oos_pairs_summary` (means and the share where OOS < IS),
and the plain sentence the number means. Combination sampling reproduces numpy's
`default_rng(seed).choice` only if we ship the same generator; we do not, so the API declares its
own sampler (`seed` → the mulberry32 generator already in `selection-risk-core.js`) and the parity vectors cover the
exhaustive case (`C(n_splits, n_splits/2) <= max_combinations`) where the two implementations must
agree to 1e-9, and the sampled case is checked on the pbo value within a stated tolerance.

**paper-evidence.** Input: a record. Runs `conformance(record, schema)` from the published
standard. Output: `valid`, `structural[]`, `semantic[]`, standard version and schema sha256.

**breadth.** Input: `sleeve_sharpe`, `average_pairwise_correlation`, optional `sleeves`, `target`.
Output: `ceiling`, `book_sharpe` at `sleeves`, `sleeves_required` for `target` (or unreachable with
the reason), `ceiling_captured`. Same identity the site publishes on `/tools/breadth`.

## 5. Docs

`/developers` is regenerated by `build-standards-and-developers.mjs`: a quickstart (issue a key,
one curl per validator), the envelope, the quota table imported from `api/_lib/limits.js`, the
receipt model, and a section titled "What a verdict does not establish". `build-api.mjs` extends
`openapi.json` with the POST paths, request schemas and the 401/413/422/429 responses; paths are
derived from a shared manifest so the document cannot name a route that does not exist (the
existing guard). Sitemap and `llms.txt` pick up the new page content through the existing builders.

## 6. Security

Size cap enforced on `content-length` before parsing and again on the read body. Strict JSON, no
NaN/Infinity, numbers coerced only from numbers, arrays length-capped before iteration. No `eval`,
no dynamic imports from input. POST validators require `Authorization: Bearer ck_live_…`; unknown
or revoked keys get 401 with the envelope. 429 carries `Retry-After` to the next UTC midnight. CORS:
`GET` receipts and status allow `*`; POST allows `*` with the key header, since keys are the
control. Errors never echo the submitted body. Function logs record endpoint, status, sizes and the
key hash prefix, never payloads. Secrets: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`,
`API_CLIENT_SALT` in Vercel env only.

## 7. Testing

- `js/moments-core.test.js`, `js/pbo-core.test.js`: parity against
  `standards/validation-api/vectors.json`, generated once by
  `~/alphaforge/scripts/export_validation_api_vectors.py` from the Python implementations on fixed
  seeds; the JS suite asserts every vector to 1e-9 (exhaustive CSCV) and the declared tolerance
  (sampled CSCV). `dsr-core.js` keeps `checkGoldenVectors` against the contract's three vectors.
- Handler tests (`api/_lib/*.test.mjs`, `api/v1/**/*.test.mjs`) inject a fake store: happy paths,
  401 unknown key, 429 at the 1,001st call, 413 oversize, 422 malformed, receipt id stability,
  envelope always has non-empty `limits`, quota headers present.
- Mutation checks recorded in the tests' docstrings: quota limit −1 must trip 429 one call earlier;
  a changed core sha256 must change the receipt id; removing a `limits` line must fail the build.
- RLS mutation test: anon read on every table returns zero rows (run once via the Supabase MCP,
  recorded in the spec's rollout notes).
- Smoke: `scripts/smoke-validation-api.mjs <base-url>` issues a key, calls every validator, fetches
  the receipt, asserts the envelope. Run against the preview deploy before production.
- `npm run verify` runs all of the above; `audit-published-numbers` treats the quota table's
  figures as sourced from `api/_lib/limits.js` (declared as a page source).

## 8. Rollout

1. Migrations via Supabase MCP `apply_migration`; RLS mutation test.
2. Vercel env vars added with the CLI (production + preview).
3. `vercel deploy` preview → smoke script → `npm run verify` → production through the normal
   hourly deploy (or `vercel --prod` after the phase, per the working cadence).
4. `/developers` and OpenAPI live in the same deploy as the functions, never before.

## 9. Open items stated, not hidden

The free tier pauses after a week of inactivity; the daily keep-alive is the mitigation and the
health monitor gets a check for it. Abuse beyond quotas (many keys from rotating clients) is bounded
by compute caps, not prevented; Vercel's firewall is the escalation path and is a separate owner
decision. Receipts are reproducible but unsigned by design.
