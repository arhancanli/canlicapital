# The saving against a plain agent (2026-09-26)

Generated by `summarize.mjs` from `plain.json` and `mcp.json`; do not edit the figures by hand.

The same 24 benchmark tasks, three passes each, gpt-5.4-mini, run one arm after the other:

- **mcp**: this server (0.6.0), local mode, company data read from canlicapital.com.
- **plain** (the control, `--arm plain`): no Canli Capital tools. A web fetch that reaches any public https URL except canlicapital.com, sending the User-Agent SEC EDGAR's API asks for, and a calculator that includes the normal CDF and its inverse. It is what an agent without this server works with. Its tool results are cut at 400,000 characters, a size a model's context holds, so truncation does not make the control cheaper than it would be.

Rate-limit refusals (HTTP 429) were waited out and retried in both arms, so the plain arm's times include those waits; compare tokens and accuracy, not time.

Per correct answer, the server used **94.3% fewer tokens** than the plain agent. In total tokens for the same tasks it used 83.2% fewer, while answering 97.2% correctly against 33.3%.

- **Company data** is where the saving is largest: per correct answer 99.1% fewer tokens. 12 of the plain arm's 13 fetches for these tasks downloaded a company's whole EDGAR file (Apple's is 3.8 MB), which the model then read again on the next turn.
- **Validation arithmetic** costs the plain agent fewer tokens per attempt, because it has no tool list to read, but it answered 25.9% correctly; per correct answer the server used 15.8% fewer.
- **Limits questions** need no tool; the plain agent answers them with fewer tokens.

## Failures in the plain arm, counted as wrong

- `dsr-6`: OpenAI HTTP 400: Invalid prompt: your prompt was flagged as potentially violating our usage policy. Please try
- `co-4`: OpenAI HTTP 429: Request too large for gpt-5.4-mini on tokens per min (TPM): Limit 200000, Requested 200189. T
- `pbo-2`: OpenAI HTTP 400: Invalid prompt: your prompt was flagged as potentially violating our usage policy. Please try

Without the two prompts the provider refused as a policy false positive, the plain arm's accuracy would be 34.3%. The request that was too large is the plain approach failing on its own: one company file did not fit the provider's per-minute token allowance.

## Scope

One model, our tasks, one day. It measures this server against a capable agent without it, not against other servers. The records are the full per-run results, including every URL the plain agent fetched.
