# CanliCapital ongoing goal

Before starting a new phase, making a release decision, or continuing after chat
compaction, read `docs/goal/README.md`, `docs/goal/REQUIREMENTS.md`, and
`docs/goal/STATUS.md`. Then read the relevant entries in `docs/goal/PHASES.md`
and `docs/goal/LOG.md`. These are the user's requested continuity records.

Update STATUS and LOG at each material transition: phase start, completed change,
validation result, blocker, scope correction, deployment, or handoff. Link actual
artifacts/commands/commits. Label plans, local work, deployed changes and measured
outcomes separately. A record is not evidence that an action happened: verify the
underlying artifacts before repeating a claim. Never erase failed results to make
a phase appear complete. New user instructions take precedence; record them.

Preserve all active objectives in REQUIREMENTS. Do not substitute sitemap capacity
or local page counts for actual indexing, or backtest metrics for forward evidence.
