canli-mcp / Overfit backtests

How do I tell whether a backtest is overfit?

Count how many settings were tried and correct the Sharpe ratio for it. canli-mcp's validate_deflated_sharpe gives the probability that the true Sharpe is above zero after that many trials, and validate_overfitting, validate_reality_check and placebo_test go further, all on your machine.

Ask it

My strategy has a Sharpe of 1.4 over five years, and I tried about 40 versions. Is it real?

The agent finds the tool through canli-mcp's find_tool and runs it through run_tool. This is the call:

{
  "name": "validate_deflated_sharpe",
  "arguments": {
    "observed_sharpe_annualized": 1.4,
    "observations": 1260,
    "periods_per_year": 252,
    "skew": -0.3,
    "non_excess_kurtosis": 5,
    "effective_independent_trials": 40,
    "cross_trial_sharpe_sd_annualized": 0.5
  }
}

The tools behind the answer

From canli-mcp's tool index
ToolPackWhat it does
validate_deflated_sharpevalidationDeflated Sharpe ratio: the probability (0 to 1) that the selected strategy's Sharpe beats the best that luck gives across the variants tried, with the probabilistic Sharpe and that luck benchmark. Send the seven statistics or a return series. With every variant's returns use validate_overfitting; luck as a trial count, validate_luck_trials; a multiple-testing haircut, validate_haircut_sharpe. A deflated Sharpe or overfitting probability above or below any threshold is not admission to anything and is not a forecast.
validate_overfittingvalidationProbability of backtest overfitting (0 to 1) by CSCV: how often the in-sample best variant falls below the out-of-sample median. Needs every variant's returns (periods by variants); with summary statistics only, use validate_deflated_sharpe. A deflated Sharpe or overfitting probability above or below any threshold is not admission to anything and is not a forecast.
validate_reality_checkvalidationData-snooping tests on every variant a search tried: Hansen's SPA p-value that the best beat the benchmark only by luck, White's Reality Check, and the variants Romano-Wolf StepM finds better. Send all variants tried, not only the winners. A deflated Sharpe or overfitting probability above or below any threshold is not admission to anything and is not a forecast.
placebo_testvalidationDoes your pipeline find edges in noise? plan writes placebo files (your data's returns in random orders, so nothing is predictable); run the whole pipeline on real.csv and on each, then compare for a p-value that counts every choice it makes. Beating the placebos shows the pipeline finds more in the real order of the returns than in random orders of the same returns; it does not show the edge survives costs, capacity or the future.
